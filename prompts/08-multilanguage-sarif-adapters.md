# CodePilot — OpenCode / Gentle AI

## Working mode

- Use **Sol** for architecture, analysis, trade-offs and implementation planning.
- Use **Luna** for implementation, tests, refactoring and documentation.
- Inspect the current repository before making changes.
- Preserve existing working code unless the prompt explicitly requires replacing it.
- Do not implement future phases prematurely.
- Prefer small, reviewable changes over broad rewrites.
- Do not push, publish, or create external resources.
- Do not add secrets or real API keys.
- Run all relevant checks before finishing.
- When a dependency or tool is unavailable, document the limitation and leave the repository in a consistent state.

## Required completion report

At the end, provide:

1. Summary of implemented changes.
2. Architectural decisions and trade-offs.
3. Files created or modified.
4. Commands executed.
5. Test, lint and type-check results.
6. Remaining risks or intentionally deferred work.

# Prompt 08 — JavaScript/TypeScript and .NET analysis adapters

## Goal

Demonstrate a language-neutral architecture by adding ESLint and SARIF ingestion, including .NET/Roslyn results.

## Scope

### JavaScript/TypeScript

- ESLint adapter using JSON output.

### .NET

- Generic SARIF importer.
- Support SARIF generated by Roslyn analyzers or `dotnet format analyzers`.
- Do not execute arbitrary repository build scripts.

## Tasks

1. Implement an ESLint adapter.
2. Implement a robust SARIF 2.1 parser.
3. Normalize SARIF locations, rules, levels and fingerprints.
4. Allow users or CI systems to upload/import an existing SARIF artifact.
5. Add an optional safe .NET analysis mode only when it can be executed without running repository code.
6. Store analyzer provenance:
   - tool
   - version
   - invocation mode
7. Add fixture projects and SARIF samples.
8. Add parser and integration tests.
9. Update supported-language documentation.
10. Expose analyzer availability in the API.

## Constraints

- Do not run `npm install` on untrusted repositories.
- Do not run arbitrary MSBuild targets.
- Prefer importing existing SARIF when dependency restoration would be required.
- Validate uploaded SARIF size and structure.
- Defend against malformed or excessively nested JSON.

## Acceptance criteria

- ESLint JSON and SARIF results are normalized consistently.
- A Roslyn SARIF sample appears correctly in analysis findings.
- Malformed or oversized SARIF is rejected safely.
- The API reports which analyzers ran, skipped or failed.
- Tests, Ruff and Mypy pass.
